# Sentra Infrastructure

Infrastructure as Code for the Sentra parking system on **Google Cloud (GCP)**.

- **Terraform** (`terraform/gcp`) creates the infrastructure: VPC, firewall, static IP and one Compute Engine VM.
- **Ansible** (`ansible/`) configures the VM and deploys the application with Docker Compose.
- **Caddy** provides HTTPS automatically (Let's Encrypt) and routes traffic to the services.
- **Supabase** (PostgreSQL + Auth) stays a managed service outside GCP.

```
                         Internet
                            │  HTTPS 443 / HTTP 80 (redirected to HTTPS)
                            ▼
   ┌──────────────── GCP: asia-south1 (Mumbai) ────────────────┐
   │  VPC sentra-vpc ─ firewall: 80/443 open, 22 restricted     │
   │                                                            │
   │  VM sentra-server (e2-standard-2, Ubuntu 24.04, static IP) │
   │  ┌──────────────────── Docker Compose ──────────────────┐  │
   │  │  caddy :443 ─┬─ /         → frontend  (React, nginx) │  │
   │  │              ├─ /api/*    → backend   (Flask :5000)  │  │
   │  │              ├─ /ai/*     → ai-service (FastAPI)     │  │
   │  │              └─ /ws       → ai-service (WebSocket)   │  │
   │  └──────────────────────────────────────────────────────┘  │
   └────────────────────────────────────────────────────────────┘
                            │ HTTPS
                            ▼
                Supabase (PostgreSQL, Auth)
```

| Path | Service |
|---|---|
| `https://<domain>/` | Admin dashboard |
| `https://<domain>/api/...` | Flask backend (`/api/health` is public) |
| `https://<domain>/ai/...` | SentraAI HTTP API (`/ai/health` is public) |
| `wss://<domain>/ws?token=...` | SentraAI live camera feed |

## Repository layout

```
terraform/
  gcp/                 ← current: GCP VM, network, firewall, static IP
  aws-legacy/          ← previous AWS design (EC2 + ALB + ECR), kept for reference
ansible/
  site.yml             ← configure + deploy (roles: common, docker, sentra)
  group_vars/all/

    vault.yml.example  ← template for the encrypted secrets file
  inventory/           ← hosts.ini is generated by Terraform

```

## Cost

`e2-standard-2` (2 vCPU / 8 GB) in Mumbai plus a 40 GB disk and a static IP is roughly
**USD 60/month**, which is covered by the GCP free-trial credit (USD 300 for 90 days).
Check exact prices with the [GCP pricing calculator](https://cloud.google.com/products/calculator).
Stop the VM when not needed (`gcloud compute instances stop sentra-server`); a stopped
VM only costs its disk and IP.

## One-time setup

### 1. Google Cloud account and project

1. Activate the free trial at <https://console.cloud.google.com>.
2. Create a project (e.g. `sentra-parking`) and note its **Project ID**.
3. **Billing → Budgets & alerts → Create budget** (e.g. USD 150, alerts at 50/90/100 %).
   Untick **"Include credits"**, otherwise the free credit hides your real spend.
4. Install and configure the CLI:

```bash
# macOS: Google's installer (bundles its own Python)
curl -O https://dl.google.com/dl/cloudsdk/channels/rapid/downloads/google-cloud-cli-darwin-arm.tar.gz
tar -xf google-cloud-cli-darwin-arm.tar.gz && ./google-cloud-sdk/install.sh
# open a new terminal, then:
gcloud init                                   # log in, pick the project
gcloud services enable compute.googleapis.com
gcloud config set compute/region asia-south1
gcloud config set compute/zone asia-south1-a
gcloud auth application-default login         # credentials for Terraform
```

### 2. Local tools and SSH key

```bash
brew install terraform ansible
ssh-keygen -t ed25519 -f ~/.ssh/sentra_gcp -C "sentra-deploy"
```

### 3. Secrets for Ansible

```bash
cd ansible
cp group_vars/all/vault.yml.example group_vars/all/vault.yml
# edit vault.yml: Supabase URL + keys, SERVICE_API_KEY (openssl rand -hex 32), Stripe key
ansible-vault encrypt group_vars/all/vault.yml   # choose a vault password and keep it safe
```

`vault.yml` is gitignored. Edit it later with `ansible-vault edit group_vars/all/vault.yml`.

## Deploy

### 1. Create the infrastructure (Terraform)

```bash
cd terraform/gcp
cp terraform.tfvars.example terraform.tfvars   # set project_id (and optionally domain, ssh_source_ranges)
terraform init
terraform plan        # review what will be created
terraform apply       # ~2 minutes
```

Outputs include the static IP, the HTTPS URL and an SSH command. Terraform also writes
`ansible/inventory/hosts.ini` with the VM's IP and domain.

**Domain:** with `domain = ""` the free name `<ip>.sslip.io` is used. It resolves to your
IP with no DNS setup and gets a real HTTPS certificate. To use your own domain, create a DNS
**A record** pointing to `external_ip`, set `domain` in `terraform.tfvars`, and run
`terraform apply` again.

### 2. Configure the server and deploy Sentra (Ansible)

```bash
cd ../../ansible
ansible-playbook site.yml --ask-vault-pass
```

The first run installs Docker and builds all images (PyTorch makes the AI image large),
so expect **10–20 minutes**. It finishes by checking `https://<domain>/api/health` and prints
the dashboard URL.

### 3. After the first deploy

- **Supabase → Authentication → URL Configuration:** add `https://<domain>` to Site URL /
  Redirect URLs so Google sign-in returns to the deployed dashboard.
- **Promote your admin account** (new accounts are role `user`):
  `UPDATE users SET role = 'admin' WHERE email = 'you@example.com';`

## Day-to-day operations

| Task | Command |
|---|---|
| Redeploy after pushing code | `ansible-playbook site.yml --ask-vault-pass --tags deploy` |
| Deploy a feature branch | `... --tags deploy -e sentra_git_branch=fix/phase1-security` |
| SSH into the VM | `ssh -i ~/.ssh/sentra_gcp sentra@<external_ip>` |
| Container status / logs | `cd /opt/sentra && docker compose ps` / `docker compose logs -f ai-service` |
| Stop / start the VM (save credit) | `gcloud compute instances stop sentra-server` / `start` |
| Destroy everything | `cd terraform/gcp && terraform destroy` |

The static IP survives VM stop/start, so the domain and certificate keep working.

## Security notes

- SSH is key-only. For best security set `ssh_source_ranges = ["<your-ip>/32"]`.
- The VM has **no service account**, so a compromised VM gets no Google Cloud credentials.
- Secrets reach the VM only through the encrypted Ansible vault and are written to
  `/opt/sentra/*.env` with mode `0600`. Nothing secret is committed or baked into images.
- Containers run as non-root users, and Docker logs are rotated.

## Troubleshooting

| Problem | Fix |
|---|---|
| `terraform apply`: Compute API not enabled | `gcloud services enable compute.googleapis.com`, wait 1–2 min |
| SSH / Ansible hangs | Your IP changed: update `ssh_source_ranges`, `terraform apply` |
| HTTPS certificate not issued | Port 80 must be reachable; check `docker compose logs caddy` |
| Dashboard loads but camera feed fails | Log in as admin/operator; check `docker compose logs ai-service` |
| Google sign-in redirects to localhost | Add the domain in Supabase Auth URL Configuration |

## CI

`.github/workflows/terraform.yml` runs `terraform fmt`/`validate` and Ansible syntax check +
`ansible-lint` on every push and pull request. It needs no cloud credentials.

## Continuous deployment

Sentra-Web and Sentra-AI-Model each have a **Deploy to GCP** workflow. When CI passes on
`main`, it SSHes into the VM, checks out the tested commit, rebuilds only that repo's
containers and runs a health check. Ansible is still used for the first setup, for
secrets and for server changes.

One-time setup:

```bash
ssh-keygen -t ed25519 -N "" -f ~/.ssh/sentra_ci_deploy -C "sentra-ci-deploy"
# terraform.tfvars: ci_deploy_public_key_path = "~/.ssh/sentra_ci_deploy.pub"
terraform -chdir=terraform/gcp apply          # adds the key to the VM (in place)

for repo in Sentra-Web Sentra-AI-Model; do
  gh secret set GCP_HOST        -R Project-Sentra/$repo --body "<external_ip>"
  gh secret set GCP_KNOWN_HOSTS -R Project-Sentra/$repo --body "$(ssh-keyscan -t ed25519 <external_ip>)"
  gh secret set GCP_SSH_KEY     -R Project-Sentra/$repo < ~/.ssh/sentra_ci_deploy
done
```

To revoke CI access, remove `ci_deploy_public_key_path` and run `terraform apply`.
